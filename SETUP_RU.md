# Установка профиля GrimVeqsum

## Вариант A — создание через подключённый GitHub (проще)

1. Открой https://github.com/new
2. Введи **GrimVeqsum**, выбери **Public** и включи **Add a README file**.
3. Создай репозиторий и сообщи об этом в чате: файлы из подготовленного комплекта можно добавить в этот репозиторий напрямую через подключённый GitHub.

Ниже — полностью самостоятельная установка без дополнительных действий в чате.

## Вариант B — самостоятельная публикация с компьютера

### 1. Создай специальный GitHub-репозиторий

1. Открой https://github.com/new
2. В поле **Repository name** введи **GrimVeqsum** (в точности как твой логин).
3. Выбери **Public**.
4. **Не ставь** галочки Add a README, .gitignore и License: репозиторий должен быть пустым для указанного ниже способа публикации.
5. Нажми Create repository.

GitHub показывает README из публичного репозитория `GrimVeqsum/GrimVeqsum` непосредственно на главной странице профиля.

### 2. Опубликуй готовые файлы

Распакуй архив в удобную папку на своём компьютере и выполни в терминале **из этой папки**:

```bash
git init
git add .
git commit -m "feat: design GitHub developer profile"
git branch -M main
git remote add origin https://github.com/GrimVeqsum/GrimVeqsum.git
git push -u origin main
```

Используй уже настроенную авторизацию GitHub. Если push через HTTPS потребует пароль, нужна авторизация через менеджер учётных данных/токен или SSH, а не пароль от GitHub.

Адрес результата: https://github.com/GrimVeqsum

## 3. Включи настоящую анимацию активности

1. Открой `GrimVeqsum/GrimVeqsum` → **Actions**.
2. Разреши workflows, если GitHub это предложит.
3. Выбери **Refresh contribution snake** → **Run workflow**.
4. Если появится ошибка Git Push (403), зайди в **Settings → Actions → General → Workflow permissions**, установи **Read and write permissions** и запусти workflow снова (доступность настройки зависит от прав репозитория).

Первоначальный `assets/snake.svg` — только визуальная заглушка с пометкой PREVIEW, **не выдаваемая за реальные данные**. Workflow заменит её реальной анимацией истории contributions; затем обновление запланировано два раза в неделю.

## 4. Что можно и чего нельзя сделать в GitHub README

README позволяет использовать Markdown, таблицы, SVG, изображения, ссылки и некоторые HTML-теги. Он **не изменяет** настоящие элементы интерфейса GitHub: шапку сайта, левую колонку профиля и системный график contributions.

Главная картинка, стек и карточки проектов — собственные SVG в `assets/` и работают без сторонних сервисов. Внешние карточки статистики/граф активности используют `github-readme-stats.vercel.app` и `github-readme-activity-graph.vercel.app`; если те сервисы недоступны, эти изображения могут не загрузиться. В GitHub при этом остаются собственные графики и данные активности.

## 5. Правки

- Заголовок и описание: `README.md`.
- Баннер и графика: `assets/*.svg`.
- Генерация SVG из изменяемых параметров: `tools/generate_assets.py` (Python 3, сторонние библиотеки не нужны).
- Автоматическое обновление snake: `.github/workflows/snake.yml`.
- Контакты: в README используется адрес почты, уже указанный в публичном профиле. Ссылки LinkedIn/Telegram пока не добавлены, чтобы не придумывать адреса.

Для локальной проверки SVG достаточно открыть файлы в браузере. Для проверки README целиком открой его на GitHub после публикации.
